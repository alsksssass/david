# 애자일 개발 방법론

## 1. 애자일 개발 방법론의 개념
애자일(Agile)은 ‘빠르고 유연한’이라는 의미로, **빠르게 변화하는 요구사항에 맞추어 지속적으로 개선해 나가는 소프트웨어 개발 방식**이다.  
과거에는 계획을 매우 상세하게 세우고 전체 기능을 모두 구현한 뒤에 한 번에 제공하는 방식(폭포수 모델)이 많았다. 그러나 실제 현장에서는 요구사항이 계속 바뀌기 때문에, 처음 세운 계획대로 진행되는 경우가 거의 없다.  
애자일은 이런 문제를 해결하기 위해 **짧은 주기(1~2주)로 계획 → 개발 → 테스트 → 배포를 반복**하며, 매 반복마다 점진적으로 기능을 완성해 나간다.

---

## 2. 애자일 개발 방법론의 장점
### ✔ 빠른 피드백
주기가 짧기 때문에 실제 사용자의 의견을 빠르게 얻고 즉각 수정 가능하다.

### ✔ 요구사항 변화에 강함
처음 계획이 완벽할 필요가 없다. 변화가 오면 그때그때 반영한다.

### ✔ 리스크 감소
전체 프로젝트 후반에 문제가 발견되는 대신, 매 스프린트마다 문제를 조기에 발견한다.

### ✔ 고객 중심적 개발
“고객이 진짜 원하는 가치”를 중심으로 개발한다.

---

## 3. 애자일 소프트웨어 개발 선언 (Agile Manifesto)
2001년 17명의 개발자와 실무 전문가들이 정리한 선언문이다.

### **애자일은 다음의 가치를 더 중요하게 여긴다**
1. 프로세스와 도구보다 **개인과 상호작용**
2. 방대한 문서보다 **작동하는 소프트웨어**
3. 계약 협상보다 **고객과의 협력**
4. 계획을 따르기보다 **변화에 대응**

---

## 4. 애자일 개발 12가지 원칙
1. 고객 만족을 위해 빠르고 지속적인 소프트웨어 전달
2. 개발 후반에도 요구사항 변경 환영
3. 작동하는 소프트웨어를 자주 제공
4. 비즈니스 담당자와 개발자의 긴밀한 협업
5. 동기 부여된 개인 중심의 프로젝트 구성
6. 대면 커뮤니케이션을 가장 효과적인 전달 방법으로 인정
7. 작동하는 소프트웨어가 진척의 핵심 지표
8. 지속 가능한 개발 속도 유지
9. 기술적 우수성과 좋은 설계에 지속적 관심
10. 단순함을 극대화
11. 자율적인 팀이 최선의 아키텍처와 설계 도출
12. 팀은 정기적으로 돌아보고 개선점을 찾아 적용

---

## 5. 애자일 개발 방법론이 필요한 이유
- 요구사항이 자주 바뀌는 환경(모빌리티, 웹서비스, 모바일앱 등)
- 빠른 시장 출시가 중요한 제품
- 고객 피드백 기반으로 기능을 수정해야 하는 서비스
- 초기 단계에서 모든 기능을 명확히 정의할 수 없는 프로젝트

---

## 6. 애자일 실천 방법론 소개

### ✔ (1) 스크럼(Scrum)
가장 널리 사용되는 애자일 기법  
**정해진 기간(스프린트)** 동안 목표를 정하고 팀이 역할을 나누어 실행한다.

- 스프린트(1~2주)
- 스프린트 회고
- 스프린트 리뷰
- 스탠드업 미팅
- 역할: 스크럼 마스터, PO(Product Owner), 개발팀

### ✔ (2) 칸반(Kanban)
작업 흐름 시각화 중심.  
“해야 할 일 → 진행 중 → 완료”와 같은 보드를 사용하여 한눈에 작업 상태를 확인한다.

- WIP 제한(동시에 작업하는 양 제한)
- 빠른 흐름과 병목 지점 파악에 유리

### ✔ (3) 익스트림 프로그래밍(XP)
기술적 실천 중심. 품질 향상에 강점.

- TDD(Test Driven Development)
- 페어 프로그래밍
- 지속적인 통합(CI)
- 리팩토링
- 단순한 설계

---

## 7. MVP(Minimum Viable Product)
### ✔ 개념  
“**최소 기능 제품**”.  
사용자가 ‘가치’를 느낄 수 있는 최소 기능만 포함한 제품.

### ✔ 애자일에서 MVP가 중요한 이유
- 불필요한 기능 개발을 방지
- 시장 반응을 빠르게 확인
- 초기에 리스크를 크게 줄임
- "완벽한 제품"이 아니라 "빠르게 테스트 가능한 제품"을 목표로 함

### ✔ 예시(모빌리티 경로 추천 서비스)
- 처음부터 모든 길찾기 기능을 만들 필요 없음
- **기본 경로 하나만 추천**하는 기능만 만들어도 충분함
- 이후 사용자 데이터와 피드백을 바탕으로 개선

---

## 8. 요약
애자일은 **짧은 반복 주기, 빠른 피드백, 변화 대응, 고객 중심 개발**이라는 특징을 가진다. 스크럼·칸반·XP 등 다양한 실천방식과 MVP 전략을 통해 빠르고 효율적인 개발이 가능하다.
